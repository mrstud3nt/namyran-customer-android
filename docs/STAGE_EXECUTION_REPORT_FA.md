# گزارش اجرای بررسی اپ مشتری و Stage

تاریخ: ۴ نوامبر ۲۰۲۶ — این گزارش تحویل نسخه نهایی نیست.

## دامنه

مخزن: https://github.com/mrstud3nt/namyran-customer-android

شاخه: `codex/stage-core-integration`؛ بدون ادغام یا انتشار Production.

## یافته‌های قابل بازتولید

- سورس مبنا: `1797e38f01c14b16a97174dcebeff49875565ee1`.
- رابط فعلی Kotlin/Compose است، اما آفلاین است: مجوز INTERNET ندارد، `BACKEND_ENABLED=false` است، لایه API ندارد و فهرست خدمات و دستگاه‌ها ثابت‌اند.
- صفحه زنده https://stage.namyranservice.ir/service-request/ و اسکریپت `assets/js/frontend.js` در افزونه `namyran-service-core` بررسی شدند.
- فایل‌های بارگذاری‌شده در صفحه برچسب نسخه `2.0.0-alpha.5.81` دارند. این برچسب، تأیید مستقل نسخه نصب‌شده یا نسخه دیتابیس نیست.
- داده زنده `NSC_DATA` شامل ۴ خدمت، ۶ گروه دستگاه، دستگاه‌ها و زیرنوع‌ها، نسخه ردیف کاتالوگ، حالت‌های مجاز خدمت، ۱۲ برند عمومی، ۷ برند نصب و ۴ بازه زمانی پیشنهادی است.
- مدل و شرح مشکل در فرم بررسی‌شده ورودی آزاد هستند؛ فهرست مستقل مدل، مشکل، شهر یا ظرفیت قابل رزرو در `NSC_DATA` وجود ندارد. این به معنی نبود قطعی آن‌ها در کل Core نیست.
- بازه زمانی پیشنهادی فرم نباید ظرفیت قابل رزرو و تأییدشده تلقی شود.
- فهرست REST زنده شامل مسیرهای OTP، درخواست، پیگیری و درخواست‌های مشتری است. مسیرهای v2 بررسی‌شده برای دسترسی، محدوده، تأییدها، فایل و ممیزی هستند؛ صرف مشاهده نام مسیر، قرارداد کامل و کارکرد آن را اثبات نمی‌کند.
- bootstrap با `action=nsc_frontend_nonce` بدون Origin، پاسخ `nsc_bootstrap_origin_denied` داد. با Origin و Referer همان Stage، پاسخ `success=true` و فیلدهای نشست دریافت شد. هیچ nonce یا کوکی‌ای در مخزن ذخیره نشده است. بنابراین رد شدن فراخوانی بدون Origin به‌تنهایی مانع قطعی Native نیست.
- اتصال مدیریتی Stage چند بار HTTP 403 با صفحه BitNinja داد. WPVibe هنگام بررسی به محدودیت مصرف روزانه رسید. سورس کامل افزونه و تنظیمات مدیریتی جاری در این اجرا خوانده نشدند.

- دو فراخوانی `otp/session` و `my-requests` با نشست عمومی ولی بدون احراز هویت مشتری، HTTP 403 و `nsc_customer_session_denied` دادند؛ این فقط رد دسترسی بدون ورود را تأیید می‌کند.

## تغییرات این شاخه

- اضافه شدن ۷ تست JUnit در مسیر استاندارد `app/src/test` برای اعتبارسنجی پیش‌نویس فعلی.
- اجرای `testDebugUnitTest` و `lintDebug` در بررسی Pull Request و نگهداری گزارش‌ها حتی در صورت خطا.
- تست قدیمی `tests/RequestRulesTest.kt` یک برنامه مستقل بود و در workflow قبلی اجرا نمی‌شد.
- هیچ قابلیت اتصال به Core در این تغییرات پیاده‌سازی یا نهایی اعلام نشده است.

## اعتبارسنجی

- دو بررسی ایستای Python محلی اجرا شدند و پاس شدند؛ این نتیجه تست اتصال یا Compile اندروید نیست.
- Gradle 9.6.0، Java 17 و SDK 36 آماده شدند. تلاش Build محلی هنگام دریافت Android Gradle Plugin شکست خورد؛ لاگ تفصیلی خطای شبکه در پراکسی تنظیم‌شده را نشان داد. تلاش دوباره با تنظیم پراکسی جاری نیز موفق نبود؛ علت دقیق تلاش دوم تأیید نشده است. از این خطا نتیجه نمی‌گیریم نسخه AGP نامعتبر است.
- Build قبلی main، اجرای GitHub Actions شماره `41861324021`، موفق ثبت شده است؛ این Build قدیمی و آفلاین است و آزمون سرتاسری یا نسخه نهایی درخواست‌شده نیست.
